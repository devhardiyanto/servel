# Servel v2.3.0

## PHP extensions

- **Settings → PHP & Node → PHP extensions** lists the extensions that ship with each installed PHP version. Turn one on or off with a switch.
- Changes go into that version's `php.ini`, so they apply to every project and terminal that uses the version.
- Before each change Servel backs up `php.ini` (the last 5 are kept next to it). Afterwards it starts PHP once to check: if PHP reports a startup error, or the extension did not change state, the old `php.ini` is put back and the reason is shown.
- On Windows, `extension_dir` is set to the absolute `ext` folder when needed, so extensions load no matter which folder PHP runs from.
- Extensions that need downloading (redis, xdebug, imagick, ...) are not installed for you. Put the matching DLL in the `ext` folder and it shows up in the list.

## HTTPS certificates for PHP (Windows)

- PHP on Windows has no certificate list, so HTTPS calls through curl fail with error 60. **Fix HTTPS certificates** sets `curl.cainfo` and `openssl.cafile` for the selected PHP version.
- It uses the certificate bundle from Git for Windows when installed. Without Git, it exports the Windows trusted roots to Servel's data folder instead.

## Dev servers no longer outlive Servel

- On Windows, dev servers are tied to Servel: if Servel crashes or is ended from Task Manager, Windows stops them too.
- On every platform, Servel remembers which dev servers it started. When it opens after an unclean exit, it stops the ones still running, checking each process's start time so an unrelated process that reused the ID is left alone.

## Upgrading

- From v2.1.0 or later: **Settings → About → Update sekarang**.
