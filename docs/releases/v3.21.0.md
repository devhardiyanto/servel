# Kova v3.21.0 — Runtimes di distro WSL dan Add tool

Rancangan: canvas Flow L (L1–L6).

## Added

- **Runtimes › Windows | WSL · <distro>** (L1–L4, Windows). Pilihan lokasi muncul bila ada distro WSL. Di distro, Kova menjalankan mise di dalam distro (`wsl.exe -d <distro> --exec bash -lc 'exec mise "$@"'`; argumen diteruskan sebagai argv, bukan teks shell):
  - daftar versi terpasang, versi global, dan project WSL yang memakainya;
  - Install, Set as global, Use in project (menulis `mise.toml` project di distro), Remove;
  - distro tanpa mise: **Install mise in <distro>** (`curl https://mise.run | sh`, ke `~/.local/bin` pengguna di distro).
  - Versi pertama sebuah tool di distro langsung menjadi global, seperti di Windows sejak v3.15.4.
- **Add tool** (L5–L6). Tab baru untuk tool mise lain: Bun, Deno, Rust, Java, Ruby, .NET, Zig, Elixir, Erlang, Terraform, kubectl, pnpm, atau nama tool mise apa pun (mis. `aqua:cli/cli`). Versi terbaru langsung dipasang di Windows atau di distro WSL. **Remove tab** menghapus tab; versi yang terpasang tetap ada sampai di-uninstall.
- Versi untuk tool tambahan boleh berbentuk selain angka (`latest`, `temurin-21`).

## Catatan

- PHP extensions tetap hanya untuk PHP di Windows.
- Bagian *Version manager* dan *Repair* di bawah halaman masih tentang mise di Windows.
- Cancel install di distro menghentikan `wsl.exe`; mise di distro bisa sempat menyelesaikan unduhan yang sedang berjalan.

## Juga di rilis ini (v3.17.1–v3.20.0, dirilis bersama v3.21.0)

### Kova v3.20.0 — project dengan Dockerfile atau compose

Rancangan: canvas Flow K (K1–K7).

#### Added

- **Project settings › Run with: Command | Dockerfile | Compose** (K1, K6). Pengganti command manual seperti `wslc remove -f … & wslc build … && wslc run …`.
  - **Dockerfile**: Kova menghapus container lama `kova-<nama>`, menjalankan `build -t kova/<nama>` di folder project, lalu `run --rm --name kova-<nama> -p 127.0.0.1:<port>:<port container>`. Variabel tab Environment dan `PORT` diteruskan sebagai `-e NAMA` (nilainya diambil engine dari environment proses, tidak ditulis ke baris perintah). Di Docker, container bisa bergabung ke network service Kova (`servel_default`), sehingga MySQL terjangkau sebagai `servel_mysql:3306`.
  - **Compose** (hanya engine Docker): `docker compose -f <file> -p kova-<nama> up --build`. Service compose yang juga ada di Kova (misalnya redis) bisa dilewati (`--scale <svc>=0`) supaya memakai service Kova. Network default compose bisa disamakan dengan network service Kova.
  - Log build dan run tampil di Logs seperti project biasa; status Running mengikuti port project.
  - **Stop** (atau proses berhenti sendiri) menghapus container (`rm -f` / `compose down`), sehingga Start berikutnya tidak bentrok nama atau port.
- **Overview** menampilkan *Runs in: Container · kova/<nama>* atau *Compose · <file>*.

#### Catatan

- WSL containers belum punya network bersama dan compose: di engine itu, container project menjangkau service lewat port di PC, dan Run with: Compose menampilkan peringatan untuk beralih ke Docker.
- Langkah dijalankan lewat script sementara (PowerShell / sh) yang menghapus dirinya; setiap argumen dikutip terpisah.

### Kova v3.19.0 — custom service dan menu ⋯ per service

Rancangan: canvas Flow J (J1–J8).

#### Added

- **Services › Add service** (J1–J3). Service di luar katalog, misalnya Elasticsearch, Meilisearch, atau Keycloak: nama, image, port di container dan di PC, Environment (`KEY=VALUE`), folder data di container (disimpan di volume `servel_<id>_data`), **Ready when** (port menjawab, atau HTTP 2xx/3xx/401/403 pada sebuah path, dicek dari PC), dan **Connect values** (`{port}` = port di PC). Custom service tampil di grup *custom* dengan chip *custom*, dan bisa dipakai seperti service bawaan: profil, tray, start bersama project, Connect, Change port.
  - Definisi dirapikan backend: container selalu `servel_<id>`, hanya volume bernama milik service itu (tanpa bind mount ke folder PC), port di PC ≥ 1024, id tidak boleh sama dengan service bawaan.
- **Menu ⋯ per service** (J4–J8):
  - **Restart**.
  - **Open shell**: terminal baru di dalam container (`wslc exec -it` / `docker exec -it`, bash bila ada, selain itu sh).
  - **Change port…** (dialog v3.18).
  - **View logs**: membuka panel service di tab Logs.
  - **Delete data…**: konfirmasi destruktif; service berhenti, container dan volume dihapus, lalu start lagi kosong. MySQL dan PostgreSQL menawarkan backup `.sql` ke Downloads lebih dulu (`mysqldump --all-databases` / `pg_dumpall`), dicentang secara default.
  - Custom service: **Edit service…** dan **Remove service…** (opsional sekaligus menghapus datanya; profil berhenti menyebutnya).

#### Catatan

- Nama subperintah hapus volume di WSL containers dicoba `volume remove` lalu `volume rm`.
- Open shell dan Delete data memerlukan engine yang berjalan.

### Kova v3.18.0 — port: siapa yang memakai, dan apa yang bisa dilakukan

Rancangan: canvas Flow I (I1–I11).

#### Added

- **Pemilik port** (I1–I4). Bila Start project ditolak karena port dipakai program lain, panel detail menyebut programnya dengan nama dan PID (Windows: `Get-NetTCPConnection` + `Win32_Process`; Linux: `ss`; macOS: `lsof`). Pilihan:
  - **Use <port berikutnya>**: port project diganti ke port bebas terdekat lalu Start.
  - **Stop <program>…**: dialog konfirmasi (program, command, PID). Kova menghentikan program itu, lalu Start project. PID diperiksa ulang dengan waktu mulainya, jadi proses lain yang kebetulan memakai PID yang sama tidak tersentuh.
- **Not answering dengan port yang dicetak app** (I5–I6). Kova membaca URL lokal (`http://localhost:3000/`, `http://127.0.0.1:8000`, `http://0.0.0.0:5173`) dan frasa `listening on :8080` / `listening on port 8080` di output. Bila project tidak menjawab di port-nya tetapi app mencetak port lain, banner menawarkan **Use <port> for <project>** dan **Open localhost:<port>**. Baris koneksi database (`localhost:5432` tanpa `http://`) tidak dihitung.
- **Services › Change port** (I7–I9). Port di PC untuk tiap service bisa diganti (di dalam container tetap). Container dibuat ulang saat start; volume tetap. Tersedia di tab Connect dan di banner "Port is used by another program", yang sekarang juga menyebut programnya dan bisa menghentikannya. **Use the default port** mengembalikan port bawaan.
- **Terminal here membawa ENV project** (I10–I11). Terminal yang dibuka dari panel atau menu project mendapat `PORT`, `SERVER_PORT`, `SERVER_HOST`, variabel Environment aktif, dan versi mise project, sehingga `php artisan migrate` dari terminal memakai nilai yang sama dengan Start. Baris pertama terminal menyebut variabel yang dipasang. Windows memakai script PowerShell sementara (Windows Terminal tidak mewarisi environment), Linux/macOS script sh sementara; keduanya menghapus dirinya saat dijalankan. Project *Run inside WSL* membuka terminal di distro dengan `WSLENV`.
